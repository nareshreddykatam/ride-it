# Supabase environment variables

Each app that uses `@ride-it/supabase` (currently: passenger, driver, admin —
not marketing) needs its own `.env.local` with these three variables. Next.js
reads env files per-app, not from the monorepo root, so copy the matching
`.env.example` inside each app folder rather than relying on one shared file.

| Variable | Where to find it | Exposed to browser? |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase dashboard → Project Settings → API | Yes |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase dashboard → Project Settings → API | Yes (safe — protected by Row Level Security) |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase dashboard → Project Settings → API | **No — server-only, never prefix with NEXT_PUBLIC_** |

No Supabase project has been created or connected yet — this repo only has
the client/server/helper code in `packages/supabase` prepared. Until real
values are filled in, any code that calls these helpers will throw the
clear "Missing environment variable" error from `packages/supabase/src/env.ts`
rather than failing silently.

## Google Maps environment variables (Phase 9)

Unlike Supabase, **the app must remain fully usable without these** — see
`packages/maps/src/env.ts` and `PHASE_9_MAPS_LOCATION_LIVE_TRACKING_REVIEW.md`.
No key configured = every map falls back to the existing demo map
(`@ride-it/maps`'s `MockMap`, clearly labeled "Demo map — not live GPS"),
not a crash.

| Variable | Apps | Exposed to browser? | Google Cloud product |
|---|---|---|---|
| `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` | passenger, driver, admin | Yes — restrict by HTTP referrer in Cloud Console | Maps JavaScript API |
| `NEXT_PUBLIC_GOOGLE_MAPS_MAP_ID` | passenger, driver, admin | Yes | Map Styles (Map IDs) — optional, falls back to `DEMO_MAP_ID` |
| `GOOGLE_MAPS_GEOCODING_API_KEY` | passenger only | **No — server-only** | Geocoding API |
| `GOOGLE_MAPS_ROUTES_API_KEY` | passenger, driver | **No — server-only** | Routes API |

No real key exists in this environment, and `maps.googleapis.com` is not
reachable from this sandbox's network at all — none of this has been
executed against the live Google Maps platform. See the Phase 9 review
document for exactly what was and wasn't verified.

## Payment environment variables (Phase 11)

Same non-fatal-degradation principle as Maps: **the app must remain fully
usable without these.** `isPaymentGatewayConfigured()` (`@ride-it/payments`)
gates every gateway call — Cash and Driver UPI work with zero payment
configuration; "Ride It Online" shows an honest "not available" state
instead of crashing when unconfigured.

| Variable | Apps | Exposed to browser? |
|---|---|---|
| `RAZORPAY_KEY_ID` | passenger, driver, admin | Returned via Route Handler responses only (never a `NEXT_PUBLIC_*` var) — this is Razorpay's own intended client-side usage for its Checkout.js widget |
| `RAZORPAY_KEY_SECRET` | passenger, driver, admin | **No — server-only** |
| `RAZORPAY_WEBHOOK_SECRET` | passenger only (canonical webhook endpoint) | **No — server-only** |

No real Razorpay account or credentials exist in this environment — see
`PHASE_11_PAYMENTS_FINANCIAL_INTEGRITY_REVIEW.md` for exactly what was
and wasn't verified without them.

## OTP delivery — MSG91 (Supabase Send SMS Hook)

Supabase Auth remains entirely responsible for OTP generation and
verification (`signInWithOtp`/`verifyOtp`, unchanged) — this only changes
*how the SMS gets sent*. These are **Supabase Edge Function secrets, not
Next.js app env vars** — they live only inside
`supabase/functions/send-sms-hook`'s runtime, never in any `apps/*/.env*`
file, and are never readable by browser code.

| Secret | Set via | Purpose |
|---|---|---|
| `SEND_SMS_HOOK_SECRET` | `supabase secrets set` | Standard Webhooks signing secret (format `v1,whsec_<base64>`) — verifies the request genuinely came from Supabase Auth, not an arbitrary caller. Self-generated (not a vendor credential); Supabase Auth's own Send SMS Hook config must hold the identical value. |
| `MSG91_AUTH_KEY` | `supabase secrets set` | MSG91 account auth key. Get from MSG91 dashboard → API → Auth Key. |
| `MSG91_TEMPLATE_ID` | `supabase secrets set` | The DLT-approved OTP template ID (MSG91 dashboard → OTP → your template). India requires this to be a real, TRAI-DLT-registered template — an unregistered/mismatched template is rejected at the carrier level, not by MSG91 or this code. |

Without `MSG91_AUTH_KEY`/`MSG91_TEMPLATE_ID` set, the hook returns a clear
500 rather than silently pretending to send — see
`supabase/functions/send-sms-hook/index.ts`. Enabling the hook itself
against the live project (pointing Supabase Auth at the deployed
function URL + `SEND_SMS_HOOK_SECRET`) is a Supabase Dashboard step
(Authentication → Hooks → Send SMS hook) — deliberately not automated
by this codebase; see the implementation report for why.

## Push notifications — Firebase Cloud Messaging

Client-side config (six `NEXT_PUBLIC_FIREBASE_*` vars + the VAPID key) is
documented inline in each app's `.env.example` — see those files. The
send-side is a second Edge Function, `supabase/functions/send-push`,
with its own project-level secrets (again: Edge Function secrets, not
app env vars):

| Secret | Set via | Purpose |
|---|---|---|
| `PUSH_DISPATCH_SECRET` | `supabase secrets set` **and** `select vault.create_secret(...)` | Shared secret between the DB trigger (`_dispatch_push_for_notification()`) and this function — the same value must exist in both places. Self-generated, not a vendor credential. |
| `FCM_SERVICE_ACCOUNT_JSON` | `supabase secrets set` | The full JSON key for a Firebase service account with the Firebase Cloud Messaging API Admin role. Firebase Console → Project settings → Service accounts → Generate new private key. **This one is a real secret — never commit it, never log it.** |
| `FCM_PROJECT_ID` | `supabase secrets set` | The Firebase project ID the messages are sent under. |

Without `FCM_SERVICE_ACCOUNT_JSON`/`FCM_PROJECT_ID` set, `send-push`
returns `{ skipped: true, reason: "fcm_not_configured" }` with HTTP 200 —
a notification's in-app inbox row is never affected by push being
unconfigured.
